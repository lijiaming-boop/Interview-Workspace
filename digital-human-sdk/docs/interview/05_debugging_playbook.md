# 调试方法与案例

## 1. 30 秒能力摘要

调试数字人链路不能从最终视频反推答案，而应把系统拆成 PCM、Mel、Matcher、模型、Render 和 Publisher 六个可验证阶段。先建立不变量，再给同一个 session、turn、seq 和 PTS 做关联，找到数据第一次偏离预期的位置。修复完成后必须用最小回归测试复现原问题，并明确哪些外部环境没有覆盖。

## 2. 通用调试闭环

1. **稳定复现**：固定模型、头像、音频、线程数和随机性。
2. **定义不变量**：形状、范围、时间戳、序号、EOS 和队列容量。
3. **分层观测**：每层只回答输入是否正确、处理是否正确、输出是否正确。
4. **构造对照**：静音/语音、短/长、CPU/GPU、单线程/多线程、固定 face/不同 audio。
5. **最小化根因**：把网络、编码和 UI 从复现中移除。
6. **最小修复**：只改变违反不变量的部分。
7. **回归与边界**：增加确定性测试，说明仍未验证的平台、模型或服务。

## 3. 必须关联的字段

| 类别 | 字段 |
|---|---|
| 请求 | session_id、turn_id/epoch、request_id |
| 媒体 | seq、PTS、duration、sample frames、fps |
| 数据 | shape、dtype、channel order、min/max/mean、finite ratio |
| 流水线 | worker state、queue depth、residence time、EOS/FATAL/SKIP |
| 性能 | ingress time、stage begin/end、emit time |
| 发布 | codec time base、packet PTS/DTS、重连和写包错误 |

高频路径不应每帧同步打印 INFO。更好的方式是采样日志、环形事件缓冲和聚合指标，出错时再导出关联窗口。

## 4. 故障树

### 没有视频输出

依次检查：

1. VideoRaw 是否进入；
2. 人脸检测是否成功；
3. Matcher 是否获得完整 Mel 窗；
4. 是否因 A/V 阈值 SKIP；
5. 模型是否输出有限值；
6. Render 是否进入 DROP/DUPLICATE；
7. OutputFrame 是否被推入队列；
8. Bridge/Publisher 是否仍在运行。

### 嘴型不随语音变化

依次检查：

- PCM RMS 是否随语音变化；
- Mel 是否有限且时间维不恒定；
- `80 × 16` 是否转置正确；
- face 前三通道是否正确遮罩；
- 固定 face、切换两段 audio 时模型输出是否变化；
- 输出是否在 mask/ROI 融合阶段被原图覆盖。

### 音画不同步

先区分：

- 输入 PTS 错；
- Matcher 选择了错误 Mel 窗；
- 排队延迟大但媒体 PTS 正确；
- Render 调度迟到；
- FFmpeg time base 转换错误；
- 打断后 PTS 回退。

### Stop 卡住或进程退出

检查每个线程阻塞在哪里、Stop 是否能唤醒 not_empty/not_full、HTTP/FFmpeg/PortAudio 是否支持取消、回调是否在持锁状态重入，以及析构前是否仍有 joinable thread。

## 5. 案例一：修正 Mel 预处理后，口型问题仍未闭合

### 现象

模型能输出人脸，视频也能生成，但不同语音的嘴型变化弱或近似相同。历史排查首先发现 Mel 预处理与训练契约不一致。

### 错误假设

直接判断“模型权重坏了”。模型文件存在且推理成功，只能证明执行路径成立，不能证明输入分布正确。

### 关键证据

- PCM 能量正常；
- Mel 形状存在，但值域、方向或归一化与训练契约不一致；
- 修正预处理后，固定 face 的音频 A/B 输出响应比历史记录仍只有约 0.04%。

### 根因链

排查确认了一个必要问题：预处理参数和归一化不匹配，使模型看到偏离训练分布的输入。但修正后模型仍然对音频不敏感，说明最终问题没有闭合，权重、blob 契约或模型转换仍需使用已知良好基准继续验证。

### 验证

逐层导出 PCM、Mel 和最终 ncnn 输入，检查 shape、有限值、范围和两段音频差异。为已确认的预处理错误增加固定输入数值回归；再用已知良好模型或 golden output 做 A/B，只有口型响应恢复后才能宣称问题最终解决。

详细历史见 [Mel 预处理修复](../bugfix/mel_preprocess_fix.md)。它记录的是“修复必要的预处理错误，但模型响应仍待验证”，不能表述为口型问题已经解决。

## 6. 案例二：短 TTS 有音频但没有视频

### 现象

短回复能够产生 AAC，却没有 H.264 帧；长回复有时正常。

### 根因

某一层把“当前队列为空”误认为“整个生产过程结束”。上游 worker 可能已经取走数据但尚未产生下游结果，瞬时空队列不构成完成协议。

### 修复原则

- 使用显式 EOS；
- EOS 按数据顺序传播；
- 只有收到下游 EOS 才确认排空完成；
- 短输入作为独立回归用例。

这个案例适合解释 happens-before、异步完成语义和为什么轮询队列大小不可靠。历史记录见 [全链路闭环验收](../guides/end_to_end_validation.md)。

## 7. 案例三：音频时钟翻倍或非线性增长

### 现象

双声道时视频越来越落后，或运行越久音频时钟增长越快。

### 量纲检查

```text
正确：累计 sample frames / sample_rate × 1000
错误一：interleaved sample 数 / sample_rate × 1000
错误二：每轮把累计值再次累加
```

第一种错误在双声道下产生 2 倍时钟；第二种错误会产生近似 O(N²) 增长。

### 回归

用 1 秒 mono、1 秒 stereo、多个不规则 chunk 和长时间累计测试，验证末尾时钟接近 1000 ms 且与分片方式无关。

历史案例见 [Bug 修复总结](../bugfix/bug_fix_summary.md)。

## 8. 案例四：Pimpl Move 后析构崩溃

### 现象

对象移动后，源对象离开作用域时崩溃，或无音频设备环境中清理失败。

### 根因

默认 Move 把源对象 `impl_` 置空，但析构或 Destroy 无条件解引用；同时第三方库可能只完成部分初始化。

### 修复原则

- 显式定义 Move 或明确禁用；
- 析构容忍空 impl 和部分构造；
- 第三方资源使用独立 RAII wrapper；
- 对 moved-from 对象只承诺可析构和可重新赋值。

案例见 [Pimpl Move 语义修复](../bugfix/pimpl_move_semantics_fix.md)。

## 9. 当前值得继续排查的案例

以下是审查发现而非已完成修复：

- Pause 只改变状态，worker 仍继续处理；
- DUPLICATE 分支不推进调度时钟，也不进入 OutputFrameQueue；
- EOS drain 的尾帧可能只走回调；
- 打断会重置上层 PTS，但核心 Mel 序号和 Publisher 时间线仍继续；
- StreamPublisher 并发 Open/Close 缺少完整状态机；
- ConversationSession Stop timeout 可能被 Bridge 的无限 drain 绕过。

面试中可以把它们讲成“代码审查发现 → 风险证明 → 目标修复 → 应增加的测试”，不能声称已经修复。

## 12. 高频追问

### 为什么不能靠日志猜问题？

日志只能证明某段代码执行过，不能自动证明数据契约正确。需要关联 seq/PTS、形状、值域和阶段输出，并用对照实验排除其他层。

### 如何证明是模型问题？

先证明预处理、blob、shape 和输入响应正确；再用固定输入比较已知基准输出或替换后端。没有这些证据时，“模型坏了”只是猜测。

### 如何保存可重放现场？

保存配置、版本、模型 SHA、有限窗口内的 packet metadata 和必要的脱敏输入，记录线程/队列事件。重放工具必须能复现同一顺序或显式注入目标时序。
