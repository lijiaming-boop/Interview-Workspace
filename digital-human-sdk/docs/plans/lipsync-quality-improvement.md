# 口型细节与高清回贴改造方案

日期：2026-10-27。本文是基于当前工作区源码的设计方案。第一步效果对比结论由用户提供；新增高清方案尚未进行模型训练、效果评测或运行时改造。

更新：用户已执行第一步对比并确认原版混合方案更好。本文第一阶段改混合/遮罩的建议已停止推进；保留原版权重和遮罩。当前执行范围以[第二步详细设计](hd-reference-color-enhancement-design.md)为准：增加高清参考、独立颜色校正与可开关增强，原版像素混合继续保留。本文下方的第一阶段内容仅留作历史方案记录，不是待执行任务。

## 1. 推荐决策

当前路线：**保留已验证的原版回贴 → 高清参考、颜色校正和可开关增强 → 按效果决定是否评估高分辨率口型模型**。

第一阶段选型已由用户完成，结论为保留原版。第二阶段改善局部画质；第三阶段提升生成能力。不能用放大、锐化代替口型生成能力的提升。

优先保留现有 C++/ncnn 路线作为轻量后端；有 NVIDIA GPU 的场景，另行验证 MuseTalk 1.5 后端。尚未明确部署硬件，因此不预设两条路线都能达到实时。

## 2. 当前代码证据与待验证原因

| 已确认的实现 | 可能影响 | 处理方式 |
| --- | --- | --- |
| `models/wav2lip-source.json` 记录模型人脸输入为 6×96×96、输出为 3×96×96；`model_inferencer.cpp`、`output_processor.cpp` 也包含固定尺寸 | 低分辨率生成区域放大到原图后缺少真实高频细节 | 分离模型尺寸与回贴尺寸；长期更换或训练高分辨率生成器 |
| `PipelineConfig::mouth_generated_blend_weight` 默认 0.7，`OutputProcessor` 最终通过像素加权混回原图 | 原嘴型与新嘴型不一致时可能出现双唇线、闭嘴残影；有效生成权重是 0.7×mask | 对比现有 direct 模式，使嘴部核心完全采用生成结果 |
| `generatePreciseMouthAlphaMask96()` 基于输入人脸关键点制作遮罩，默认进行 11×11 高斯模糊 | 原图闭嘴时，遮罩可能不足以覆盖生成后张开的嘴；小嘴区域可能被过度半透明化 | 遮罩覆盖原嘴与生成嘴，并保留不透明核心，向外羽化 |
| `Process()`、`ProcessROI()` 对 96×96 输出固定执行强度 1.0 的锐化，再通过线性插值逆变换 | 可能强化低分辨率锯齿和光晕；不能补出真实牙齿纹理 | 把锐化改为配置项，先关闭建立基线，再评估增强后的轻度锐化 |
| `doColorBlend()` 是像素混合，不是肤色统计校正 | 虽可减弱色差，也会重新混入旧嘴型 | 用嘴周皮肤的低频颜色校正替代核心嘴区混合 |
| SDK 配置转换当前未传递上述回贴控制项 | 修改底层 Pipeline 参数不一定能覆盖公开 SDK 调用路径 | 为 SDK 配置、映射、必要的 C API 增加一致的参数传递 |

上述实现事实不等于已经确认的视觉根因。当前没有拿同一段输入完成逐阶段对比，不能直接断言模型权重损坏。

另一个需要验证的因素是预处理约定：本项目使用眼部对齐，官方 Wav2Lip 推理使用检测框裁脸后缩放。当前 TorchScript 权重来自另一个发布源，应核对它实际需要的裁剪范围、通道顺序、归一化和音频特征。官方实现只能作为对照，不能直接当作该权重的训练约定。

## 3. 第一阶段：修复回贴，分离模型问题与渲染问题

### 3.1 建立定位基线

同一输入、同一模型、同一 PTS 保存五种结果：原图嘴部、模型原始 96×96 输出、仅放大结果、逆变换后的生成块、最终融合结果。同时输出遮罩和关键点叠加图。

- 原始输出已经唇线错误、牙齿糊连：优先检查输入约定、音频时间窗及生成器能力。
- 原始输出正常、最终结果出现双唇线：优先修遮罩、旧嘴混合、坐标映射。
- 单帧清晰、播放闪烁：优先处理定位抖动与生成/增强的时间一致性。

复用现有 `examples/mouth_fusion_ab_test.cpp`、`scripts/run_mouth_ab_comparison.py`，对比 baseline、direct、outer-feather。脚本含既有硬件路径和输入约定，运行前需适配本机，不能把源码中的硬件字符串当作当前设备检测结果。

### 3.2 改融合策略

嘴部核心生成权重设为 1；只在外侧过渡带逐渐降低权重；过渡带之外保留原图。

先使用项目已有 outward feather 路径做低成本对照，96 空间的 2～4 像素仅作为实验起点。转到高清空间后，羽化宽度应由嘴宽和投影尺度决定，不能沿用固定像素数。

动态遮罩至少覆盖“原嘴区域 ∪ 生成嘴区域”，再适量扩张。生成区域可由解析模型获取；轻量版本可使用验证过的最大张嘴包络。检测不可靠时回退到有边界约束的包络，不能因为未检出就裁掉生成口腔。

张嘴幅度较大时，覆盖必要的唇周形变区域，避免只换口腔、嘴外皮肤保持完全静止造成僵硬感。

### 3.3 颜色、几何与时间稳定

- 历史建议中颜色校正的部分继续细化到第二步：在嘴外皮肤环带估计低频亮度/色度差异，对生成块做有限幅度校正，同时继续保留原版像素混合。
- 检查正逆变换的一致性，避免多次缩放。图像与遮罩使用同一坐标定义。
- 静态头像复用几何参数；视频输入仅稳定人脸定位、变换和遮罩。不要直接平均连续嘴部图像，否则会拖慢口型、产生运动重影。
- 多频段融合只作为边缘仍明显时的对照项。保持口腔核心硬约束，防止融合重新带回原嘴纹理。

本阶段验收结果应是：旧嘴残影减少、张嘴不被截断、边缘色差减轻。它不承诺解决 96×96 模型本身的牙齿和唇纹不足。

## 4. 第二阶段：高清参考与局部细节增强

建议数据流：

```text
高清原图 ──→ 高清对齐参考（直接从原图采样） ──────────┐
       └─→ 模型约定的 96×96 输入 → 口型生成 → 局部增强 ─┤
                                                   ↓
                         颜色校正 → 高清遮罩 → 逆变换 → 原尺寸输出
```

维护两套用途不同的数据：生成器输入仍为 96×96；参考和融合区域根据原图实际人脸大小选取，例如先验证 384×384。高清参考必须直接取自原图，不能从 96×96 放大得到。

局部增强模块分两步验证：

1. 先做轻量 2×/4×超分辨率基线，比较“插值放大”和“学习式补细节”的收益及耗时。皮肤、胡须等未改变几何的区域优先保留原图细节。
2. 若收益不足，再训练参考图引导的嘴部细化器：输入生成嘴、高清参考和修改区域遮罩；参考图嘴内区域应屏蔽或限制特征使用，防止网络把原来的闭嘴纹理复制回来。

GFPGAN 可作为现成修复模型的效果基线。若模型要求完整对齐人脸，就提供完整人脸上下文，最后只采纳允许修改区域的结果；不能直接把任意嘴巴小块当作人脸输入。生成式修复补出的细节是估计值，不能视为恢复了原本不存在的信息。

增强模块必须检查是否改了嘴形、牙齿数量或人物特征。逐帧增强也可能产生闪烁，因此需要短序列训练或在可靠运动估计下约束时间一致性；快速张闭嘴、遮挡和跟踪失败时，不应把上一帧纹理强行传播过来。

实现时为增强后的图像重新组合坐标映射，包含像素中心约定；图像、关键点、遮罩、逆变换必须一致。不能直接把 96 空间的逆矩阵原封不动用于 384 空间。

本阶段可以减轻“嘴部糊、周围清晰”的割裂感，但若生成嘴的几何或发音对应关系错误，仍需进入第三阶段。

## 5. 第三阶段：提升生成模型能力

### 路线 A：现有轻量部署优先

保留 ncnn 口型生成后端，以局部细化器作为主要增量。若需要原生 192/256 输出，需调整生成网络结构、训练配置与同步监督，并重新训练/微调、导出和验证，不能只改 `face_size`。

模型侧训练条件：

- 使用有权使用的高清音画同步说话视频，覆盖张嘴、闭嘴、圆唇、露齿、侧脸、胡须和不同光照。
- 训练参考帧与目标帧分离，遮住目标嘴部信息，避免模型学习复制嘴型。
- 按人物划分训练和验证集，防止同一人的相邻帧泄漏造成虚高效果。
- 联合像素重建、感知细节、音画同步和时间一致性约束；对抗损失后期开启并控制权重，防止“更锐但不同步”。同步判别器需适配裁剪/分辨率，或在经过验证的下采样输入上工作。
- 没有真实配对目标的音频改配任务，不强行使用原嘴图像作像素级监督。
- 先验证浮点模型效果，再评估 FP16；INT8 必须对嘴型和牙齿细节单独回归。

当前仓库未发现配套训练流程，只有已导出的模型资产。要做这条路线，需要补充可训练模型实现和数据流程，不能仅凭导出 TorchScript 文件假定已具备微调条件。

### 路线 B：GPU 画质优先

把 MuseTalk 1.5 作为原生 256×256 人脸区域生成的候选，先以独立 Python/CUDA 进程完成效果验证，再决定是否导出到其他推理引擎。

它使用 Whisper 音频特征及 VAE 图像编码，不能把现有 Wav2Lip 的 80×16 Mel 或 ncnn 权重直接替换过去。需要抽象后端接口，让每个后端声明自己的音频特征、裁剪约定、输入输出尺寸和上下文要求。

保留现有 C++ 的会话、PTS、队列和输出能力；新的推理后端返回生成块及几何信息。静态头像可缓存参考特征。需明确音频上下文带来的首帧延迟，并测量逐帧或小批量推理，不能用大批量离线吞吐替代实时指标。

官方报告的 30fps+ 来自 Tesla V100，不能推定本机达到同样速度。官方也列出了唇形/胡须保留不足及抖动等局限，因此 256×256 候选仍需通过同一套融合和视频质量评测。

## 6. 工程改造范围

| 模块 | 改造内容 |
| --- | --- |
| `FaceAligner` / `VideoProcessor` | 保留高清参考与几何信息；生成输入使用各后端的裁剪约定 |
| `ProcessedFaceData` | 区分推理尺寸、参考尺寸及对应变换，逐步替换仅适用于 96 的字段命名 |
| `FaceMaskGenerator` | 支持任意尺寸、动态嘴形覆盖、不透明核心和向外过渡 |
| `OutputProcessor` | 拆出增强、颜色校正、融合；锐化可配置；按实际输出尺寸处理，错误形状显式报错 |
| `ModelInferencer` / `InferenceWorker` | 提取后端接口，声明音频与图像输入约定；保留 ncnn 实现 |
| SDK 配置与映射 | 传递画质模式、回贴参数、增强开关，验证公开入口实际生效 |
| 性能与质量工具 | 复用分阶段计时，增加模型前后、增强前后、融合前后的可比较输出 |

实时性能不足时，优先关闭增强或选择轻量后端。增强步骤不能形成新的持续队列积压；任何回退都保持 PTS 对应关系。

## 7. 验收与实施顺序

先固定同一组图片/视频、语音、分辨率、编码设置和硬件，按单变量实验比较：baseline → direct → outward feather → 动态高清遮罩/颜色校正 → 增强 → 高分辨率模型。

建议首轮使用至少 10 个身份，每人覆盖静音、正常说话、快速说话和大幅张嘴；训练路线另设未见过人物的验证集。

| 验收项 | 方法 |
| --- | --- |
| 口型准确 | 同步模型评估结合逐帧人工检查，重点检查闭唇、圆唇与快速切换；同步评分不等同于画质评分 |
| 细节与接缝 | 同比例嘴部放大视频盲评，检查双唇线、牙齿糊连、色块、胡须断裂和嘴型截断 |
| 时间稳定 | 正常速度播放，结合运动对齐后的区域误差检查闪烁；不把正常张闭嘴当作应消除的变化 |
| 原图保留 | 在修改区和羽化带之外，检查编码前像素差；有损编码后的误差单独统计 |
| 实时能力 | 按目标硬件测量端到端吞吐、各阶段 P50/P95、队列水位、首帧延迟与音画偏移 |

可把 25fps 作为首轮目标，即流水线平均每 40ms 持续交付一帧；串行阶段总耗时与多线程稳态吞吐分别评估。吞吐达标后，还要确认队列不增长、首帧和口型延迟可接受。所有目标都是待测指标。

现有 `tools/lipsync_quality_analysis.cpp` 中与原图嘴部进行的 PSNR/SSIM 比较可用来观察变化，但不能作为口型正确性的主要指标，因为正确说话本来就应改变原图嘴型。像素指标只用于有真实配对目标的数据，或确定不应变化的区域。

执行顺序：

1. 第一阶段对照已由用户执行，采用原版混合方案作为固定基线。
2. 按第二步详细设计补齐高清参考、配置透传与坐标回归。
3. 分别验证颜色校正、参考皮肤细节补偿和可开关神经超分，记录效果与性能增量。
4. 在相同素材上验证 MuseTalk 1.5；依据目标硬件、延迟与效果决定是否引入新后端。
5. 若两条现成路线仍不满足要求，再投入高清口型模型或参考引导细化器训练。
