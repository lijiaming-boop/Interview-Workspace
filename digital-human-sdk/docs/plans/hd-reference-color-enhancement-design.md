# 第二步设计：高清参考、颜色校正与可开关增强

日期：2026-10-27。状态：设计交付，接口为拟新增；尚未修改运行时代码、下载增强模型或执行效果评测。

## 1. 已确定的基线

用户已执行第一步对比，原版混合方案更好。本方案以该结果为依据：保留原版混合权重、遮罩算法及已有口型模型，不再推进 direct / outward-feather 替换。

令原图为 O、原版投影到原图的遮罩为 A、生成权重为 w（当前默认 0.7），当前两次混合在理想浮点计算下等价于：

```text
F = A·G + (1-A)·O
Y = w·F + (1-w)·O = w·A·G + (1-w·A)·O
```

本次仅把 G 换成处理后的 G_new，仍按原来的两次混合执行。不能为减少一次运算而合并公式，因为中间 uint8 舍入会造成结果差异。全部新开关关闭时直接调用原有路径，要求编码前逐像素一致。

## 2. 数据流与职责

```text
原图 O + 既有对齐几何 ──→ 高清参考 R（直接采样原图） ─────┐
                                                       │
96×96 模型输出 → 原版锐化/放大基底 → 可选神经超分 → 皮肤细节补偿
                                                       ↓
                                     可选颜色校正 → G_new
                                                       ↓
                  逆变换至原图 ROI → 原版遮罩融合 → 原版 w 混合
```

高清参考用于颜色统计与安全区域的皮肤纹理；神经超分用于生成块的细节估计。单独增加高清参考不会让 96×96 的牙齿、口腔自动获得真实高清信息。

原始模型输入保持现状，高清参考不再送入当前 Wav2Lip。高清参考也不参与重新决定脸部位置，避免另一次检测造成两套坐标漂移。

## 3. 高清参考：384 对齐画布，同一套几何

首版固定使用 384×384 对齐参考，与 96×96 形成 4 倍关系；这是候选工作尺寸，不是模型生成分辨率。原图脸部较小时不会凭空获得更多纹理，增强可按有效像素尺度降低强度。更大的原图脸部仍可能需要后续更高尺寸或新模型。

已有 `FaceAlignerResult::M` 是原图到 96 空间的变换，`M_inv` 是其逆变换。将矩阵转为 3×3 齐次形式，定义：

```text
s = 384 / 96 = 4
T = [ s  0  (s-1)/2 ]
    [ 0  s  (s-1)/2 ]
    [ 0  0      1    ]

M_original_to_reference = T · M
M_reference_to_original = M_inv · inverse(T)
```

T 与 resize 的像素中心约定对应：x_ref = s·(x_96+0.5)-0.5。直接只缩放矩阵前两列会漏掉平移项。实现需用角点、中心和往返投影测试确认 OpenCV 调用的方向和标志。

用 `M_original_to_reference` 直接采样原图生成 R；不能将已有 96 图放大冒充 R。保留与原对齐裁剪范围一致的来源有效区，生成 `valid_mask`，排除裁剪外/图像外填充值。参考采样、生成块放大及关键点映射共用上述约定。

建议在 `OutputProcessor` 内延迟构建参考，仅为真正要渲染的帧构建，避免将高清图复制到现有多个队列。

拟新增内部数据：

```cpp
struct HdReference {
    cv::Mat bgr;                    // 384×384，CV_8UC3，原图直接采样
    cv::Mat valid_mask;             // 384×384，CV_8UC1
    cv::Mat color_sample_mask;      // 仅用于拟合颜色的可靠皮肤样本
    cv::Mat skin_detail_weight;     // CV_32FC1，仅允许补偿纹理的皮肤区
    cv::Mat ref_to_original;        // CV_64F，2×3
};
```

这些是辅助掩码，不能替换或扩大最终融合使用的原版 `face_mask`。

缓存与所有权：

- 每个 OutputProcessor 持有自己的参考缓存；缓存内容视为只读，复用缓冲时不能覆盖仍被使用的数据。
- 静态图片在确认来源像素、几何与配置一致后复用；未来可接头像版本号，但当前不能假定 `source_id` 已具备头像版本语义。
- 首版可对相关原图裁剪逐行完整比较，确认相等后复用；现有稀疏采样签名不能作为新参考缓存的唯一判等依据。
- 动态视频未确认一致时逐帧重建参考；换头像、图像尺寸变化或几何变化时清空相关缓存和颜色状态。

## 4. 颜色校正：只拟合皮肤色差，保留原版混合

颜色校正发生在增强后、逆变换和最终混合前。拟合样本来自未做神经超分的生成基底与高清参考，避免增强产生的纹理影响估计。

### 4.1 取样范围

根据已有嘴部关键点构造嘴外环带，并限制在两侧可靠皮肤区域；排除嘴唇、口腔、牙齿、鼻孔、参考无效区、过暗/过曝区和明显高梯度区域。首版几何规则无法可靠识别所有胡须和遮挡，因此有效样本不足或区域差异过大时跳过，不强行拟合。

生成图和参考图先在相同有效尺度上低通处理，再比较颜色。辅助环带可以超出最终回贴遮罩，但修正后的图像仍仅通过原版遮罩写回。

### 4.2 首版算法

使用浮点 Lab 颜色空间，BGR 先归一化到 [0,1]。这里 L 的范围为 [0,100]，a/b 使用浮点原始范围，不能套用 8 位 Lab 的缩放。

在可靠样本上计算逐通道稳健偏移，先做偏移校正，不做逐帧方差比例拉伸：

```text
delta_raw = median(R_low - G_base_low, reliable_skin_samples)
delta = clamp(delta_raw, channel_limits)
G_new_lab(p) = G_enhanced_lab(p) + strength·q(p)·delta_smoothed
```

其中 q 是平滑的颜色应用权重：皮肤为主，唇区减弱，牙齿/口腔设为 0。保护范围应覆盖原嘴及保守张嘴包络，避免原图闭嘴导致保护区过小。q 仅控制校正强度，不承担最终融合。

实验起点：strength=0.5；偏移上限 ΔL=±5、Δa/Δb=±3。数值均为待验证参数，不是效果结论。若无法确认牙齿/口腔保护可靠，首版仅在确定的皮肤区域应用校正。

仅平滑三通道颜色参数，不平均嘴部图像。使用按 PTS 间隔计算的时间平滑系数，遇到头像变化、时间轴跳变或大幅几何变化重置；跳过拟合时不无限沿用旧参数。首个可靠样本直接初始化。

颜色校正和原版 `ColorBlend` 是两个独立步骤：前者调整生成块颜色，后者继续执行用户验证更好的原版像素混合。

## 5. 增强：三种模式，分别验证收益

| 模式 | 行为 | 能解决的问题 |
| --- | --- | --- |
| Off | 不增加纹理补偿或神经超分；高清参考/颜色仍可单独开启 | 隔离高清几何与颜色收益 |
| ReferenceDetail | 在可靠皮肤区补入受限的参考高频细节 | 减少嘴周皮肤发糊，与原图纹理衔接 |
| NeuralSR | 对生成块做 4×超分，并可叠加安全皮肤细节补偿 | 尝试改善唇线、牙齿等生成细节观感 |

### 5.1 皮肤参考细节

令 B 是原版锐化后的 96 输出经固定插值放大到 384 的基底。将高清参考先降到 96 再放回 384，得到与低分辨率信息尺度接近的参考基底，提取差值：

```text
D_ref = R - Upsample(Downsample(R, 96), 384)
G_detail = B + detail_strength·skin_detail_weight·Clamp(D_ref)
```

优先只在亮度上补偿，差值在浮点域计算并限幅。权重在嘴唇、口腔、牙齿、明显位移区为 0；唇边保留额外安全距离并平滑衰减。detail_strength 先从 0.15 起评估。

参考嘴周也可能因张嘴产生形变。若无法确认局部纹理对应稳定，直接关闭该区域的参考补偿。最终原版混合本来已保留部分原图纹理，所以新增补偿必须小幅度验证，避免双重纹理和过锐。

### 5.2 神经超分

首轮以已有官方 ncnn 实现支持的 `realesrnet-x4plus` / `realesrgan-x4plus` 做候选对照，不预设哪一个效果更好，也不承诺实时。`realesr-general-x4v3` 可列为后续轻量候选，但其导出与本项目 ncnn 兼容性需要另行验证。

输入完整的模型生成人脸块，保留上下文；输出只通过原版嘴部遮罩写回。首版禁止对整张高清原图做全局增强。

```text
S = SR(G_raw96)                       // 原始模型输出，不预先叠加强锐化
G_sr = B + sr_strength·(S - B)         // 控制相对原版基底的修改程度
G_enhanced = G_sr + 安全皮肤细节补偿    // 可由 detail_strength=0 关闭
```

sr_strength 建议以 0.25、0.5、0.75 三档离线比较。SR 的输出不能再次套用固定强度 1.0 的低分辨率锐化；B 保留旧锐化仅作为混合基底，避免同时调整多项因素。

每个候选须固定模型哈希、输入通道/值域、输出尺寸和推理选项。超分模型在 Init 时加载一次，不逐帧启动外部命令、不逐帧加载权重。新开关关闭时不加载模型、不申请增强用 GPU 资源。

通用超分没有音频条件，可能改变牙齿/唇线或逐帧闪烁，因此须检查降采样一致性与连续视频，结合盲评决定是否启用。降采样一致只能筛查部分异常，不能证明口型正确。首版不加入前后帧像素平均，以免造成口型拖影。

## 6. 原版遮罩和坐标的兼容方式

生成图从参考空间逆变换回原图 ROI；最终遮罩仍按原来的 96→原图或原图空间处理路径生成。不能把原遮罩先放大再重新羽化，也不能将辅助皮肤掩码作为新的融合 alpha。

新图像路径有额外插值，开启高清处理后不要求与原版逐像素相同；但所有新功能关闭时必须直接走旧路径，避免额外 resize/warp/颜色转换造成基线变化。

对投影后参考无效的像素，使用原路径的生成结果兜底，并在有效区边缘平滑切换，禁止将黑色填充带带入融合。输出 ROI 以原版同一范围为界，不向外扩写。

## 7. 配置与接口草案

```cpp
enum class EnhancementMode { Off, ReferenceDetail, NeuralSR };

struct HdPostprocessConfig {
    bool enable_hd_reference = false;
    int reference_size = 384;              // 首版只接受 384
    bool enable_color_correction = false;
    float color_strength = 0.5f;
    EnhancementMode enhancement = EnhancementMode::Off;
    float detail_strength = 0.15f;
    float sr_strength = 0.5f;
    std::string sr_model_prefix;           // 显式选择的 .param/.bin 资产
    bool allow_fallback = true;
    bool enable_adaptive_fallback = false; // 实验时保持关闭
};
```

放入 SDKConfig 与 PipelineConfig 共用的独立配置头，避免各层重复声明；`ToPipelineConfig()` 显式传递，`Pipeline::Init()` 一次性注入 OutputProcessor。`mouth_generated_blend_weight` 和 `mouth_outward_feather_px` 按现有基线处理，不被画质预设覆盖。

首版开关在 Init 前设置，运行期间不直接修改配置和模型实例。若随后需要播放中切换，可另增按帧边界生效的命令接口；未预先加载 SR 时不能在渲染线程临时加载模型。

依赖与失败语义：

- 颜色或增强开启而高清参考关闭：Init 报配置错误，避免设置看似生效。
- NeuralSR 请求缺少模型或后端不可用：allow_fallback=true 时显式降到 ReferenceDetail 并报告；false 时 Init 失败。
- 单帧参考无效：该帧走原路径；仅颜色样本不足：只跳过颜色步骤；单帧 SR 失败：降到参考细节或基底路径。
- 非有限数、尺寸错误或变换非法：不写入损坏结果，记录原因并回退。
- 外部调用能读到 requested_mode、effective_mode、skip/fallback 原因和计数，不能静默宣称 NeuralSR 已生效。

C API 建议新增独立、带 struct_size 的 `dh_postprocess_config_t` 与创建后的预启动配置函数。当前 create 已调用 SDK Init，因此该函数须显式支持“已初始化且未启动”状态：在调用线程校验配置、准备新后处理资源，成功后整体替换，失败则保留旧配置；不能只修改 Init 后不再读取的配置副本。保留现有 `dh_sdk_config_t` 大小，避免直接追加字段触发现有 sizeof 检查、破坏旧调用方。函数名和错误映射在实现时统一；C++ 结构变化要求使用方重新编译。

## 9. 性能、降级与验收

新增阶段计时：`hd_reference`、`reference_detail`、`sr_inference`、`color_estimate`、`color_apply`、`hd_warp`；沿用现有 render_fusion 总耗时并注明包含哪些阶段。报告 P50/P95、冷启动与稳态开销、GPU 内存和队列水位。

以目标硬件的 25fps 持续输出作为候选目标，保留首帧延迟和队列不增长要求；当前没有性能测量，不给出新增模块必能控制在若干毫秒的承诺。

可选自适应降级按窗口持续超预算触发，至少一个片段内保持模式稳定，禁止逐帧开关 SR。超预算不能中断正在进行的单次 ncnn 调用，只影响后续帧。重新启用需明确恢复条件和较长稳定窗口。默认实验关闭自适应，保证比较的模式一致。

固定使用用户已选定的原版混合方案、同一模型、音频、PTS 与编码配置，对比以下组合：

| 组别 | 高清参考 | 颜色校正 | 增强 |
| --- | --- | --- | --- |
| A | 关 | 关 | Off：原版精确基线 |
| B | 开 | 关 | Off：检查几何、额外重采样的影响 |
| C | 开 | 开 | Off：隔离颜色收益 |
| D | 开 | 开 | ReferenceDetail：隔离皮肤纹理收益 |
| E | 开 | 开 | NeuralSR，detail_strength 与 D 一致：隔离 SR 收益 |

必要时为 SR 单独增加 detail_strength=0 的辅助组。每次实验保存配置、模型哈希、有效模式和降级次数。

必须通过的验证：

1. A 与旧实现编码前逐像素相同；原版遮罩、w、锐化与输入张量保持既有行为。
2. 96/384/原图/ROI 的角点与中心投影一致，往返误差满足设定容差；有效区不带黑边；全图和 ROI 路径在重叠区一致到规定舍入容差。
3. C 在可靠皮肤区域改善色差，牙齿不染色、口腔不被提亮；样本不足能按约定跳过。
4. D 不把原图唇线或闭嘴纹理复制回来；低清原图、胡须、张嘴导致皮肤位移时允许关闭补偿。
5. E 检查闭唇、圆唇、露齿与快速说话，口型不因细节增强而明显变化；同时播放长片段检查闪烁。
6. 头像切换、参考失效、SR 模型缺失/失败、EOS 与长时间运行，输出 PTS 连续且队列不持续积压。
7. 原版融合区域之外编码前像素不变；有损编码误差单独统计。

实现拆分顺序：先做 A/B 与配置透传，再做 C，接着做 D，最后接入 E。各步分别保留开关与输出对照；不重新执行第一步的混合方案选型。

## 10. 依据与边界

- 当前源码证据：`ProcessedFaceData::original_face` 实际保存原始整帧；已有 M_inv 与关键点足以构建参考。当前 `RenderTaskData` 未转发关键点，需要补齐。
- [OpenCV 几何变换](https://docs.opencv.org/4.x/da/d54/group__imgproc__transform.html)：采样与正逆变换方向的依据；本方案的坐标组合需通过数值测试核验。
- [OpenCV Lab 转换](https://docs.opencv.org/4.x/de/d25/imgproc_color_conversions.html)：浮点值域依据。
- [Real-ESRGAN ncnn 官方实现](https://github.com/xinntao/Real-ESRGAN-ncnn-vulkan)：已列出 x4plus 系列候选；并不代表本项目已完成接入或性能验证。
- [Real-ESRGAN 官方仓库](https://github.com/xinntao/Real-ESRGAN)：general-x4v3 作为轻量候选的依据。

本方案改善局部色差、皮肤纹理和生成块细节观感；无法保证从 96×96 恢复真实牙齿、改变错误发音对应关系，或完全消除通用单帧超分的闪烁。
