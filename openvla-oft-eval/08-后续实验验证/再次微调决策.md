# OpenVLA-OFT 是否再次微调：决策与执行方案

## 决策

**现在不应直接再次微调，更不应复用上次“7 条示教 + 1000 步”的方案。**

只有在补齐高质量专家数据并通过前检后，才建议做一次 **200-step、可随时回滚的续训实验**。这次实验的目的不是立刻替换 99% 基座，而是验证“正确加载原动作头 + 原数据回放 + 难例修正”是否能提高确定性失败状态。

## 为什么上次 0% 不能证明“续训无效”

训练日志显示：

- 主 VLA 从 `openvla-7b-oft-finetuned-libero-spatial` 加载；
- 随后创建了 16,818,176 参数的 proprio projector 和 151,117,831 参数的 action head；
- 启动命令没有 `--resume True --resume_step 150000`；
- 上游 `finetune.py::init_module()` 仅在 `resume=True` 时加载这两个 checkpoint。

所以，上次实际做的是“已微调 VLA + 新 LoRA + **随机动作头/随机 proprio 投影器**”，再用 7 条轨迹训练 1000 步。0% 的首要根因是续训入口错误；小数据、全零旋转动作、脚本直线轨迹和 correction-only 训练进一步放大了问题。

## 是否值得再做

基座已达到 495/500（99%），全部失败都在抓取闭环，收益上限很小；抓取确认/重抓仍应优先于改权重。因此采用条件式决策：

1. 先完成抓取确认与失败重抓实验；若能恢复 233/378/230，不训练。
2. 只有仍存在可重复失败状态，才采集 50–200 条真实专家/人工遥操作成功轨迹；每个失败构型 5–10 条，覆盖位置、姿态和旋转修正。
3. correction 数据必须与 `libero_spatial_no_noops` 混合；禁止 correction-only。
4. 从官方 spatial 150K checkpoint 正确加载 action head/proprio，学习率 `5e-6`，先训 200 steps，每 50 steps 保存候选。
5. 分级评测 150050/150100/150150/150200，选择最早达标者，不默认选择最后一步。

## 发布门槛

| 层级 | 样本 | 通过条件 |
|---|---:|---|
| 数据前检 | 全部示教 | ≥50 条、7D 动作有限、旋转维有覆盖、两路图像与 8D proprio 齐全 |
| 目标失败态 | 每状态 ≥10 次 | 相比基座有提升，且不是单 seed 偶然成功 |
| top drawer | 50 states | ≥49/50（98%） |
| LIBERO-Spatial | 500 episodes | ≥495/500（99%），且其他任务无明显回退 |

任一层失败即停止评测并回滚。由于 495/500 与 500/500 的差异只有 5 个 episode，最终比较最好再换至少两个 seed；未达到稳定提升时继续使用基座。

## 执行

### 阿里云 PWI 环境口径

当前脚本不再假设魔搭平台，也不强制 Conda。它按以下顺序使用 PWI 上的现有环境：

1. `$OFT_ACTIVATE` 指定的激活脚本；
2. `$PWI_WORKSPACE/activate_oft.sh`；
3. `$PWI_WORKSPACE/venv_oft/bin/activate`；
4. 兼容已有的 `oft` Conda 环境；
5. 以上均不存在时才使用当前 Python。

默认工作目录是 `/mnt/workspace`；如果代码实际位于 `/root/openvla_oft_workspace/openvla-oft`，脚本会自动切换。也可显式设置：

```bash
export PWI_WORKSPACE=/mnt/workspace
export OFT_ACTIVATE=$PWI_WORKSPACE/activate_oft.sh
```

训练前必须通过：Python 3.10、NumPy 1.26.4、CUDA/BF16，以及文档验证过的
`torch 2.2.0` 或 `torch 2.5.1+cu124`。如果 PWI 基础镜像显示 torch 2.13/cu130 而驱动为
CUDA 12.4，不要直接使用该 torch；应进入已迁移的 `venv_oft`，或按环境文档换成 2.5.1/cu124。
PWI 使用 OSMesa、离线 W&B 和 HF 镜像；不兼容的 flash-attn 应卸载并使用当前仓库已配置的 SDPA。

先验证现有 PWI 环境：

```bash
cd "$PWI_WORKSPACE/openvla-oft/08-后续实验验证/scripts"
CHECK_TRAINING=1 bash 00_env_check.sh
```

如需在 PWI 重装 torch 2.5.1/cu124，文档中验证过的命令是：

```bash
python -m pip uninstall -y flash-attn
python -m pip install --index-url https://download.pytorch.org/whl/cu124 \
  torch==2.5.1 torchvision==0.20.1 torchaudio==2.5.1
python -m pip install --force-reinstall \
  -i https://mirrors-ssl.aliyuncs.com/pypi/simple numpy==1.26.4
```

不要使用 `mirrors.cloud.aliyuncs.com`，其证书域名与文档记录的 PWI/阿里云环境不匹配。

### 训练命令

```bash
# PWI 上二选一；必须以实际挂载位置为准
export PWI_WORKSPACE=/mnt/workspace
# export PWI_WORKSPACE=/root/openvla_oft_workspace

# 若已有该文件可手动激活；没有也没关系，后续脚本会自动找 venv_oft/Conda
[ ! -f "$PWI_WORKSPACE/activate_oft.sh" ] || source "$PWI_WORKSPACE/activate_oft.sh"
cd "$PWI_WORKSPACE/openvla-oft/08-后续实验验证/scripts"

TRIALS=50 bash 06_top_drawer_sweep.sh

DAGGER_RLDS_ROOT="$PWI_WORKSPACE/datasets/rlds" \
SOURCE_HDF5="$PWI_WORKSPACE/expert_top_drawer.hdf5" \
VLA_PATH="$PWI_WORKSPACE/openvla-oft-ckpts/openvla-7b-oft-finetuned-libero-spatial" \
EXTRA_STEPS=200 LEARNING_RATE=5e-6 \
nohup bash 07_dagger_loop.sh \
  > "$PWI_WORKSPACE/finetune_top_drawer_pwi.log" 2>&1 &

tail -f "$PWI_WORKSPACE/finetune_top_drawer_pwi.log"
```

脚本会在真正启动 GPU 训练前检查：150K 动作头/proprio 文件、完整 VLA 权重、原始与修正 RLDS、mixture 注册、示教条数、动作范围和旋转覆盖。旧的 7 条全零旋转数据会被直接拒绝。
