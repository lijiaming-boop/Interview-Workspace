这份资料是一套面向“魔搭 A10 GPU 实例”的 OpenVLA-OFT × LIBERO 基线评测工具包。它不会在你当前的 Windows 目录里直接运行；应当上传到 Ubuntu 22.04 GPU 实例后执行。

核心目标是：

> 下载 OpenVLA-OFT 官方模型，让机器人在 LIBERO 仿真环境执行任务，统计成功率，并整理失败视频。

主要依据是 [README.md](./openvla-oft-baseline/README.md)、[环境搭建手册](./openvla-oft-baseline/docs/01_setup_env.md) 和各执行脚本。

## 一、需要的机器环境

推荐配置：

| 项目     | 要求                                                 |
| -------- | ---------------------------------------------------- |
| 操作系统 | Ubuntu 22.04                                         |
| GPU      | NVIDIA A10 24GB；其他支持 bf16、显存≥24GB 的卡也可以 |
| CUDA     | 12.1                                                 |
| Python   | 3.10                                                 |
| CPU/内存 | 文档目标环境为8核、32GB                              |
| 磁盘     | 单套模型建议≥40GB；四套完整评测建议≥90GB             |
| 网络     | 国内 pip、conda、GitHub 代理和 hf-mirror             |
| Shell    | Bash，不是 PowerShell/CMD                            |

推荐镜像：

```text
ubuntu22.04-cuda12.1.0-py310-torch2.3.0
```

最终软件版本应为：

## 三、完整操作流程

### 第1步：运行机器自检

```bash
cd ~/openvla-oft-baseline
cd /mnt/workspace/openvla-oft-baseline

export OFT_ROOT=/mnt/workspace/openvla-oft
export LIBERO_ROOT=/mnt/workspace/LIBERO
export CKPT_ROOT=/mnt/workspace/openvla-oft-ckpts

USE_BASE=1 bash scripts/01_setup_env.sh
```

它会检查：

- GPU型号、显存和驱动；
- 剩余磁盘空间；
- CPU和内存；
- conda与Git；
- 清华 pip、hf-mirror、GitHub代理是否连通；
- 镜像自带的Python和PyTorch版本。

理想结果：

- 能看到A10和约24GB显存；
- `nvidia-smi`正常；
- Python为3.10；
- 国内源显示 `[OK]`；
- 下载一套模型至少还剩30～40GB。

如果GitHub加速失败，后续可以临时换源：

```bash
GH_PROXY=https://gh-proxy.com bash scripts/01_setup_env.sh
```

### 第2步：安装环境

推荐创建独立conda环境：

```bash
bash scripts/01_setup_env.sh
```

预计耗时30～60分钟，占用约15GB。

这个脚本会自动完成：

1. 没有conda时安装Miniconda；
2. 创建名为`oft`的Python 3.10环境；
3. 设置GitHub代理；
4. 安装PyTorch 2.2.0；
5. 克隆两个官方仓库：
   - `~/openvla-oft`
   - `~/LIBERO`
6. 安装旧版`gym==0.21.0`；
7. 安装OpenVLA-OFT和LIBERO；
8. 强制锁定`numpy==1.24.4`；
9. 检查CUDA和关键依赖。

如果非常在意时间和磁盘，可以直接使用镜像自带环境：

```bash
USE_BASE=1 bash scripts/01_setup_env.sh
```

但它会把镜像里的PyTorch 2.3.0降到2.2.0，并修改基础Python环境。除非实例只用来做这个实验，否则更推荐独立conda环境。

安装完成后可人工检查：

```bash
conda activate oft

python -c "import torch, numpy; print(torch.__version__, numpy.__version__)"
python -c "import gym, robosuite, transformers; print(gym.__version__, robosuite.__version__, transformers.__version__)"
python -c "from prismatic.vla.constants import NUM_ACTIONS_CHUNK, ACTION_DIM; print(NUM_ACTIONS_CHUNK, ACTION_DIM)"
```

应看到类似：

```text
torch: 2.2.0+cu121
numpy: 1.24.4
gym: 0.21.0
robosuite: 1.4.1
transformers: 4.40.x
NUM_ACTIONS_CHUNK: 8
ACTION_DIM: 7
```

### 第3步：先只下载Spatial模型

```bash
bash scripts/02_download_ckpts.sh spatial
```

模型默认保存到：

```text
~/openvla-oft-ckpts/openvla-7b-oft-finetuned-libero-spatial
```

约15GB。下载中断后重复同一命令即可续传。

- `config.json`
- `dataset_statistics.json`
- `*.safetensors`
- action head与proprio projector权重

缺少`dataset_statistics.json`会导致动作无法正确反归一化，不能忽略。

```bash
# 四个独立模型，共约60GB
bash scripts/02_download_ckpts.sh all

bash scripts/02_download_ckpts.sh combined
```

磁盘紧张时，推荐四合一模型。

### 第4步：前台运行冒烟测试

这是不能跳过的一步：

```bash
SMOKE=1 bash scripts/03_run_libero_eval.sh spatial
```

它会运行：

- 10个Spatial任务；
- 每任务2次；
- 共20个episodes；
- seed默认为7；
- GPU默认为0。

第一次加载LIBERO时，终端可能询问数据保存路径。输入一个可写目录，例如：

```text
/root/libero_data
```

或者：

```text
/home/<用户名>/libero_data
```

回答后会生成：

```text
~/.libero/config.yaml
```

如果没有完成这次交互就直接用`nohup`，后台任务很可能因为无法读取输入而报`EOFError`。

冒烟测试的验收标准：

- 模型成功加载；
- CUDA没有OOM；
- MuJoCo能离屏渲染；
- 能完成20个episode；
- `~/openvla-oft/experiments/logs/`出现日志；
- `~/openvla-oft/rollouts/`出现MP4视频；
- 工具包的`results/runs.jsonl`出现运行记录。

即：


预期成功率约为97.2%。A10结果与参考值相差±1～2个百分点通常可以视为复现成功。

### 第7步：运行全部评测

如果下载的是四个独立模型：

```bash

nohup bash scripts/03_run_libero_eval.sh all 50 > run_all.log 2>&1 &
```

查看进度：


如果下载的是四合一模型：


`all`会按照下面的顺序串行运行：

1. Spatial
2. Object
3. Goal
4. LIBERO-10

完整四套共2000个episodes，30小时额度很可能不够。更现实的方案是：

```bash

bash scripts/03_run_libero_eval.sh spatial 50

# 其余每套先做100条
bash scripts/03_run_libero_eval.sh object 10
bash scripts/03_run_libero_eval.sh goal 10
bash scripts/03_run_libero_eval.sh 10 10
```

这里最后一条中，第一个`10`是LIBERO-10套件名，第二个`10`是每任务次数。

## 四、评测内部到底做了什么

一次episode的执行链路是：

```text
重置LIBERO环境
→ 读取第三人称和腕部相机图像
→ 图像旋转、中心裁剪和缩放
→ 根据任务描述构造prompt
→ 加入机器人关节和夹爪状态
→ 模型一次预测8步、每步7维的动作
→ 使用checkpoint统计量反归一化
→ 转换夹爪开合约定
→ 向仿真环境连续执行8步
→ 判断任务是否成功
→ 保存日志和视频
```

其中最关键的三个数：

- `8`：模型一次生成8步动作；
- `7`：每步包含6维末端运动和1维夹爪动作；
- `8`：输入的机器人本体状态维数。

更完整的模型链路可看 [Pipeline详解](./openvla-oft-baseline/docs/02_pipeline_walkthrough.md)。

## 五、必须注意的风险

1. `numpy`必须保持`1.24.4`。出现2.x通常会让TensorFlow、robosuite或LIBERO报错。

2. 首次LIBERO运行必须处理交互问题。完成前台冒烟测试后才能放心使用`nohup`。

3. EGL退出时报错不一定是真故障。如果任务完成且退出码为0，退出阶段的`EGL_NOT_INITIALIZED`通常可以忽略。

4. 成功率低于80%时，优先检查图像中心裁剪、NumPy版本、proprio输入和checkpoint完整性。

5. 文档称`center_crop=True`已默认启用，但封装脚本没有显式传入这个参数，它依赖上游官方脚本的默认值。环境安装完成后，建议检查：

```bash
cd ~/openvla-oft
python experiments/robot/libero/run_libero_eval.py --help | grep -E "center.crop|use.proprio|num.images"
```

确认中心裁剪、本体输入和双图像输入确实启用后再做正式长跑。

6. 环境脚本会写入全局GitHub地址改写。实验结束后如需撤销：

```bash
git config --global --unset url."https://ghfast.top/https://github.com/".insteadOf
```

7. 日志、视频和汇总结果不在同一目录：

```text
~/openvla-oft/experiments/logs/     日志
~/openvla-oft/rollouts/             视频
~/openvla-oft-baseline/results/     汇总表格和索引
```

实例释放前要把三处都下载走。

8. 同一天运行多个suite时，失败案例脚本可能无法仅凭日期准确判断视频属于哪个suite；`annotation_template.csv`中的suite可能为空。正式实验最好按日期分开运行，或者人工结合日志补全。

## 六、最推荐的实际执行顺序

如果你的GPU额度约30小时，直接采用这一套：

```bash
cd ~/openvla-oft-baseline

bash scripts/00_preflight.sh
bash scripts/01_setup_env.sh
bash scripts/02_download_ckpts.sh spatial

SMOKE=1 bash scripts/03_run_libero_eval.sh spatial
bash scripts/03_run_libero_eval.sh spatial 10
nohup bash scripts/03_run_libero_eval.sh spatial 50 > spatial50.log 2>&1 &

python scripts/04_aggregate_results.py
python scripts/05_collect_failure_cases.py
```

Spatial完成并确认结果正常后，再下载或使用四合一checkpoint补跑其余三个suite。这样最节省时间，也最容易定位环境和模型问题。

自测一下：如果后台任务一启动就报`EOFError`，应先检查`~/.libero/config.yaml`是否存在；如果成功率异常低，第一批应检查`center_crop`、NumPy版本和checkpoint统计文件。
