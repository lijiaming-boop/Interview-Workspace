空调 / 空压 / 报价 / 设备拓扑 · 四模块依赖总览

同一代码仓库（前端 Next.js 16 + FastAPI）下的业务线定位与共享依赖
业务模块（前端流程 + 后端管线） 共享平台层（FastAPI / M1 底座 / 外部 LLM） 跨模块数据桥（空调 → 仿真） 调用共享平台

模块耦合结论

  • 强依赖（唯一数据桥）：空调 → 仿真。走“前端 props（节能率 + sessionId）+ 后端 source_session_id 复制调研表”双通道，属上下游而非循环依赖。
  • 结构共享：空调与空压共用 Workflow.tsx 骨架与 /api 分阶段端点；差异收敛在 moduleType、提取引擎与结果面板。
  • 无耦合：报价模块与空调/空压/仿真不互传会话；空压无下游模块。

共享契约清单

  • src/lib/api.ts：全部端点与 TS 类型（session/extract/suggest/calculate/result/download/sim/quote）。
  • apps/api：路由 + 后台线程管线 + 会话写透 + SSE + 锁 + 审计。
  • .claude/skills + core/：空调/空压规则技能、plant-simulation、LLM 网关。

横切治理（不在耦合内）

  • agent/ 编排（LLMBrain/RuleBrain）与 /agent、/inbox 页面、evaluation/ 评测、Go proxy + OIDC 认证——覆盖空调/空压主链，报价/仿真各有独立 AI 通道。
