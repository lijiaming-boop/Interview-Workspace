空调模块 · 空调节能率智能测算

moduleType = air_conditioner · “上传 → 提取 → 建议 → 计算 → 完成（→ 冷站仿真）”
前端 Next.js 16 后端 FastAPI 存储/会话底座 技能/消息通道 外部模型 / 下游模块 请求/数据 异步 / 回传 / 跨模块 主流程调用

职责边界

  • 负责：空调调研表上传 → 规则提取+质检 → 填充建议（可选 LLM）→ Excel 公式节能测算 → 分项/区间结果展示与报价、方案、计算表下载。
  • 不负责：物理公式全部在模板内由 formulas 引擎确定性执行；不写仿真代码；报价/方案文档文件由后端计算管线生成（不经报价模块）。

核心数据流

  • 上传 → session → extract-and-check-data 规则脚本 → ac_extracted_data.json（含站房类型判定、完整率门禁）。
  • DataFiller.fill_data（只填 null）→ ExcelCalculator 双 sheet 上下限（含 WeatherService）→ energy_saving_rate / chiller·pump·tower_saving 区间。
  • SSE 日志回传前端；结果轮询取回；xlsx/docx 经 /api/download 下载。

模块间依赖

  • 依赖共享：lib/api.ts、分阶段端点、M1 底座、Anthropic（仅 suggest 增强）。
  • 向下游：节能率 + sessionId → 仿真/设备拓扑模块（source_session_id 桥，见该模块架构图）。
  • 平行：与空压共用 Workflow.tsx 与 /api 管线；报价模块独立不消费本会话。
