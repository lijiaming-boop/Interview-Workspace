# 服务器部署指南

本文档描述如何把本系统完整部署到一台 Linux 服务器上，包括 OIDC 登录闭环
（默认用内置的**轻量 mock OIDC**（约 50MB 内存，零外部镜像依赖）完整验证
认证闭环；生产环境切换到真实 IdP 见下文）。

## 架构与端口

```
浏览器 ──▶ proxy:8080（Go 网关，OIDC 登录 + 身份头 HMAC 签名，唯一公网入口）
              │ BACKEND_URL
              ▼
          web:3000（Next.js BFF，/api rewrites 透传签名身份头，仅内网）
              │ API_INTERNAL_URL
              ▼
          api:8000（FastAPI + Alembic/Postgres + Redis，仅内网）
          oidc:8081→宿主机 8081（mock OIDC 测试 IdP，登录页跳转用）
```

- `proxy` 是唯一对外端口：**8080**（应用）与 **8081**（测试 IdP）需要防火墙放行。
- `web`/`api` 仅内网可达，绕过网关直连拿不到有效签名身份头，API 会 401。

## 前置要求

| 项 | 要求 |
|---|---|
| 系统 | Linux x86_64（Ubuntu 22.04 / Debian 12 / RHEL 系均可） |
| Docker | 24+，含 `docker compose` v2 插件 |
| 资源 | 建议 2C / 4G / 40G |
| 端口 | 8080（应用）、8081（测试 IdP，可经 `OIDC_PORT` 换端口）对浏览器可达 |
| 网络 | 服务器需能拉取 Docker Hub 镜像及 pypi / npm / goproxy.cn 包源 |
| 工具 | curl、sed、openssl（一般系统自带） |

## 一键部署

```bash
# 1. 把代码弄到服务器（git clone，或 scp -r 整个目录；注意脚本与模板保持 LF 行尾）
git clone <你的仓库地址> conditioner_saving && cd conditioner_saving
#    或已有代码则: git pull

# 2. 一键部署（脚本会自动生成/补全 .env、构建启动、冒烟验证）
./scripts/deploy_server.sh http://<服务器IP>
#    不带参数时脚本会探测本机 IP 并让你确认

# 3. 登录使用
#    浏览器打开 http://<服务器IP>:8080 → 跳转 mock OIDC 登录页
#    测试账号: test / test123456（roles 含 sr，具备 API 特权角色）
```

`deploy_server.sh` 做的事情：

1. 生成/补全 `.env`（缺什么补什么，不覆盖已有键；`AUTH_SECRET` 自动随机生成）
2. 按 `PUBLIC_BASE_URL` 派生 `REDIRECT_URI` 与 `OAUTH_SERVER_URL`（mock IdP）
3. `docker compose -f docker-compose.yml -f docker-compose.oidc.yml up -d --build`
4. 轮询等待 oidc / proxy / api 就绪
5. 运行 `scripts/verify_deployment.sh` 冒烟验证（见下）

## 冒烟验证内容

`./scripts/verify_deployment.sh [BASE_URL]` 依次验证：

1. proxy `/health` 匿名可达
2. 未登录访问 `/` 被 307 到 `/login`，并跳转 OIDC 授权端点
3. **无头 OAuth 登录**：curl 模拟浏览器走完 mock IdP 登录 → 回调 → 拿到签名会话 Cookie
4. `/api/health` 经 `proxy → web(BFF) → api` 全链路可达
5. 上传样例调研表 → 以 `mode=deterministic`（零 LLM 成本）跑完 Agent 主线，
   轨迹终态为 `completed`

全部通过即可确认认证闭环与业务链路在服务器上完整可用。

## 环境变量说明

见 `.env.deploy.example`。关键项：

| 变量 | 说明 |
|---|---|
| `AUTH_SECRET` | proxy 与 api 共享的身份签名密钥（HMAC-SHA256），必须同值，生产必填 |
| `PUBLIC_BASE_URL` | 浏览器可达的服务器地址（`http://<IP>`），用于派生回调地址 |
| `OAUTH_SERVER_URL` | IdP 地址；**必须与 IdP 的 issuer 全等**（Keycloak 是 `http://<IP>:8080/realms/hvac`，mock IdP 为 `http://<IP>:8081`，网关按 issuer 全等校验） |
| `REDIRECT_URI` | 网关回调地址，默认 `http://<IP>:8080/oauth2callback` |
| `CLIENT_ID` / `CLIENT_SECRET` | 网关在 IdP 注册的客户端凭证 |
| `ANTHROPIC_API_KEY` | 可选；不填则 Agent 自动降级零成本规则策略 |

## 切换到生产 IdP（Casdoor 等）

> 备选：如需用 Keycloak 做测试 IdP，可导入模板 `deploy/oidc/realm-hvac.json.template`
> （hvac-proxy 客户端 + test 用户 + roles 顶层 claim 映射），并把
> `OAUTH_SERVER_URL` 指到 `http://<IP>:8080/realms/hvac`。

1. 在 IdP 侧注册客户端：回调地址 `http://<你的域名>:8080/oauth2callback`
2. `.env` 覆盖四项：`OAUTH_SERVER_URL`（必须等于 IdP 的 issuer 全称）、
   `REDIRECT_URI`、`CLIENT_ID`、`CLIENT_SECRET`
3. 重新拉起（**不叠加** oidc 文件，mock IdP 容器不再启动）：
   ```bash
   docker compose -f docker-compose.yml up -d --build
   ```
   （切换后记得移除 `.env` 里指向 mock 的 `OAUTH_SERVER_URL`，改为真实 issuer）
4. 建议：生产域名 + HTTPS（由外部 Nginx/Caddy 终结 TLS 后反代到 8080）

## 故障排查

| 现象 | 原因 / 处理 |
|---|---|
| proxy 反复重启，日志 `Failed to initialize OIDC provider` | 网关连不上 IdP。确认 8081 已发布、`OAUTH_SERVER_URL` 与 IdP issuer 完全一致（Keycloak 含 `/realms/hvac`，mock IdP 为裸地址） |
| compose 启动即报 `AUTH_SECRET 必须显式设置` | `.env` 缺必填项，重跑 `deploy_server.sh` 或手工补齐 |
| 登录页报 `Invalid parameter: redirect_uri` | IdP 侧注册的回调与 `.env` 的 `REDIRECT_URI` 不一致；改 `.env` 后重跑 `deploy_server.sh`（mock IdP 重读环境变量需 `docker compose up -d --force-recreate oidc`） |
| 能登录但 API 全 401 | `AUTH_SECRET`（api）与 `COOKIE_SECRET`（proxy）不一致；compose 已强制同值，检查是否被手工改过 |
| 上传 413 | Next.js BFF 请求体上限已调到 100mb（`next.config.ts`），仍报错检查外层反代（Nginx `client_max_body_size`） |
| 浏览器打不开 8080/8081 | 防火墙/安全组放行；云服务器还需在控制台安全组放行 |

## 安全提醒（生产必读）

- mock IdP 与测试账号（`test/test123456`）仅用于验证闭环（任何输入即视为登录成功），
  生产必须切真实 IdP 并去掉 `docker-compose.oidc.yml` 叠加。
- `AUTH_SECRET` 泄露等同伪造任意身份，定期轮换（参考 `docs/密钥轮换与历史清理.md`）。
- 建议 HTTPS 化：外部反代终结 TLS，浏览器走 `https://`，IdP 回调同步改为 https。
