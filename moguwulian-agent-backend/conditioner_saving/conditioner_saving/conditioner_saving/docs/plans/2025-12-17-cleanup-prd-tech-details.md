## 职责边界

| 维度 | PRD | 技术方案 |
|------|-----|----------|
| 核心问题 | 做什么 & 为什么 | 怎么做 |
| 技术选型 | ❌ 不写 | ✅ 详细写 |
| 架构设计 | ❌ 不写 | ✅ 详细写 |
| 业务逻辑 | ✅ 详细写 | ✅ 实现 |
| 数据定义 | ✅ 详细写 | ✅ 基于此设计 |
| 性能指标 | ✅ 写约束 | ✅ 写方案 |

## 判断标准

当犹豫某内容该不该写进PRD时:

**问题**: 如果技术用另一种实现方式,是否会影响用户体验或业务结果?

- **会影响** → 可以写(作为约束)
- **不会影响** → 不该写(交给技术)

## 示例

### ✅ 可以写
- "数据上传后30秒内完成处理" (性能约束)
- "支持5-10人并发访问" (并发约束)
- "节能率偏差≤2%" (准确性约束)

### ❌ 不该写
- "使用Streamlit框架" (技术选型)
- "用pandas处理数据" (实现方式)
- "session state管理状态" (技术细节)
