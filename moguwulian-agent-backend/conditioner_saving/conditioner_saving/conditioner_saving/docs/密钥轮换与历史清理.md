## 一、为什么必须轮换（而不是只删文件）

1. `.env`（提交 `04e6ac4` 引入，`87048ce` 更新，`b2784d1` 移出版本控制）——

2. `scripts/generate_plan_doc.py`（文档生成脚本的示例配置块中**硬编码**，
   本次改造已替换为占位符）。

只要密钥未轮换，任何拿到仓库完整历史的人都仍然持有一把有效钥匙。
`.gitignore` 只能防止"下一次"，不能清洗"过去"。

## 三、清理 Git 历史（可选但推荐）

如果仓库有对外协作者/曾公开过，建议重写历史移除密钥：

```bash
# 推荐：git-filter-repo（比 filter-branch 快且安全）
# 注意：replace-text 文件中填入完整旧密钥（此处不落盘，避免二次泄露）
pip install git-filter-repo
echo "sk-你的完整旧Key==>***REMOVED***" > /tmp/replacements.txt
git filter-repo --replace-text /tmp/replacements.txt
rm /tmp/replacements.txt
git push --force --all
git push --force --tags
```

注意：
- 重写历史会使所有提交哈希变化，需**提前通知全部协作者**重新 clone；
- 即使历史清洗完成，密钥轮换仍不可省略（无法确认未被缓存/镜像）。
