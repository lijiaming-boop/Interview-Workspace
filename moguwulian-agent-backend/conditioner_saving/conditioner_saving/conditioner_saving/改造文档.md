## 一、改造起点与总览

### 1.1 起点（改造前的真实状态）

项目本是一个 Streamlit + AI 辅助脚本的 Web 工具，经 code review 确认的底子与问题：

**已有的好底子**：claude-agent-sdk + Skill 体系、Excel 物理公式引擎（formulas 库）、
三级地区推断、质量门禁、9 份标注样例调研表（文件名自带预期节能率）。

**核心问题**：agent 用得浅（纯规则脚本也起完整 agent 会话，烧钱）、编排是写死的
五阶段状态机、三份 SkillCaller 拷贝、Excel 计算失败静默降级 mock 假数据、
会话是进程内 dict、无认证授权（session_id 可枚举可越权）、无 CI 无容器、
13 个既有测试失败长期无人修。

### 1.2 改造路线（五个阶段，全部完成）

| 阶段 | 主题 | 核心产出 |
|---|---|---|
| **P1-P3** | Agent 化核心 + 评测 + 包装 | `agent/` 包（编排器/工具注册表/双决策核心/轨迹）、`evaluation/` 回归评测、README/ARCHITECTURE 重写 |
| **清理** | 工程卫生 | 删 ~100MB 垃圾、修复 16 个既有测试失败、深度模板变体适配（评测 83%→100%） |
| **M1** | 企业级平台底座 | 落库持久化、认证+ACL+审计、断点恢复、Docker/CI |
| **M2** | 用得起来 | LLM 网关+预算、HITL 审批闭环、空压线统一编排、前端轨迹回放 |
| **M3** | 用得多 | 批量测算、历史案例库、通知集成、评测集扩容 |

## 二、业务场景（改造后服务什么）

面向**暖通/空压节能售前场景**的两类用户闭环：

1. **销售（AR）**：上传客户调研表 → Agent 自主完成提取/质检/填充/计算 →
   得到节能率区间与结论摘要；数据不达标时收到"缺什么"的明确清单；
   一批项目可一次批量上传。
2. **解决方案专家（SR）**：待办收件箱处理 Agent 的求助与审批；历史测算库
   按地区/站型检索相似案例辅助报价；越权与导出全部审计可查。

四条业务线状态：空调（Agent 编排 ✅）、空压（Agent 编排 ✅，提取为 LLM 型工具）、
冷站 8760h 仿真（独立 agent 面：动态生成仿真代码）、报价生成（独立流水线 + 语义冲突检测）。

## 三、架构演进

> AI 调度架构从"claude-agent-sdk + Skill"到"AgentOrchestrator 编排"的
> 升级细节（动机/映射/Skill 归宿/安全收敛）见
> [从Skill到Agent升级改造设计.md](./从Skill到Agent升级改造设计.md)。

### 3.1 改造前

```
Streamlit 五阶段状态机 ── SkillCaller(每次一个 agent 会话) ── 规则脚本
        │                                                    Excel 公式引擎
   内存 dict 会话（无持久化、无认证、失败静默 mock）
```

### 3.2 改造后

```
Next.js（含 /agent 轨迹回放）      Docker Compose（db/api/web） + CI 门禁
        │ REST + SSE
FastAPI（路由级 ACL + 审计 + 强制认证开关）
        │
AgentOrchestrator（ReAct 循环 + 白名单硬约束 + 断点恢复 + HITL 暂停）
   ├─ Brain：LLMBrain（经 LLM 网关）│ RuleBrain（零成本，评测/离线）
   ├─ ToolRegistry：air_conditioner │ air_compressor 两套工具集，同一门禁语义
   └─ 每步落库（agent_runs/steps）+ 待办（agent_actions）+ 通知（webhook）
        │
PersistentSessionStore（SQLAlchemy：SQLite 开发 / PostgreSQL 生产）
        │
确定性引擎层：formulas Excel 公式 │ 规则提取/质检/填充 │ AirCompressorCalculator
```

**贯穿始终的设计原则**：算得准的交给公式（确定性工具，执行零 token），
看得懂的交给模型（决策/叙事/非结构化提取）；硬约束在代码里（模型绕不过），
软决策在白名单内（自主性有边界）。

## 八、答辩/汇报要点（三句话版本）

1. **边界设计**：测算精度 ≤2% 的数字全部来自确定性引擎（Excel 公式/规则脚本，
   执行零 token），LLM 只做感知与决策，硬约束白名单让自主性可被代码证明。
2. **评测驱动**：6+3 例锚点评测零成本可复现，先后揪出静默错数 bug、
   模板变体误拦、湿球数据物理违规三个真实问题，决策正确率从 83% 修到 100%。
3. **企业级闭环**：持久化+断点恢复、认证+ACL+审计、LLM 预算治理、
   HITL 求助/审批待办、批量测算与历史案例库——从"能算"到"敢给销售用"。
