# 空压机数据提取与质量检查 (LLM版)

## 功能描述

使用大语言模型智能分析空压机调研表的文本内容，提取关键信息并转换为结构化数据，同时进行数据质量检查和打回条件判断。

## 工作流程

1. **文本预处理**: 接收script提取的文本内容
2. **智能识别**: 使用LLM识别和提取关键字段
3. **数据清理**: 清理和标准化提取的数据
4. **打回条件检查**: 根据五、打回条件清单进行验证
5. **质量检查**: 评估数据完整性和准确性
6. **结果输出**: 生成JSON格式的结构化数据

## LLM提取指令

请从以下文本内容中提取空压机调研表的关键信息，并按照指定的JSON格式输出。

### 输入
- 调研表的文本内容（由script从Excel、Word、PPT等文件中提取）
- 原始文件名（用于上下文参考）

## 提取指令

### 第一部分：原始数据提取

#### 1. 项目级原始数据 (rawData.projectLevel)
- **companyName**: 企业名称，从文档标题、表头或企业信息部分提取
- **companyShortName**: 企业简称，删除"有限责任公司"等后缀，如果没有则根据企业名称自动生成
- **projectName**: 项目名称，由企业简称 + "空压系统节能项目"等后缀自动生成
- **projectLocation**: 项目所在地（省市），用于搜索平均工业用电
- **industryType**: 行业类型，用于压力波动因子匹配。取值必须为：电池、整车及电子、钢铁有色、其他。注意："新能源行业"、"光伏"、"风电"等应归类为"其他"，而非"电池"。行业归类详见附表1-1。
- **totalAnnualEnergyConsumption**: 空压系统年度总用量，单位kWh，可根据月度总耗电量求和
- **electricityPrice**: 平均电价，单位元/kWh，若无则根据项目所在地的省份查表
- **alarmPressureLowerLimit**: 现有系统报警压力（下限），单位bar，出口主管的最低允许压力
- **averagePressure**: 近14天系统平均压力，单位bar，系统实际运行平均压力
- **dailyRunningHours**: 每天开机时间，单位小时/天
- **annualRunningDays**: 年运行天数，单位天/年

#### 2. 设备级原始数据 (rawData.equipmentLevel)
每台空压机一行，包含以下字段：
- **stationId**: 站房编码/名称，站房名称不可重复
- **equipmentId**: 设备编码/名称，设备名称不可重复
- **equipmentType**: 设备类型，取值：螺杆、离心
- **brand**: 品牌
- **model**: 型号
- **manufactureYear**: 出厂年份，用于计算机龄
- **runningStatus**: 运行状态，取值：运行、备用、故障、停用
- **ratedPower**: 铭牌功率，单位kW，额定功率
- **ratedFlow**: 铭牌流量，单位m³/min，额定排气量
- **age**: 机龄，根据 manufactureYear 计算（当前年份 - 出厂年份）
- **compressorPowerFactor**: 压缩机功率因子，根据品牌和机龄查表，无法确定时默认 0.35
- **specificPower**: 比功率，计算公式：(ratedPower × 1.1) / ratedFlow



## 提取规则

1. **数值提取**: 只提取纯数字，去除单位和其他文字
2. **缺失处理**: 如果字段在文档中找不到，设置为null
3. **文本清理**: 去除多余空格、换行符和特殊字符
4. **类型转换**: 确保数值字段为数字类型，文本字段为字符串类型
5. **设备分组**: 如果有多个站房，按站房分组设备信息
6. **执行打回检查**: 根据打回条件清单进行验证

## 打回条件检查 (rejectionCheck)

### 致命错误（必须打回）
检查以下条件，如果任一条件满足，则 shouldReject = true，并在 criticalIssues 中记录：

1. **现有系统报警压力缺失**: alarmPressureLowerLimit 为空或 ≤0
   - 错误信息: "请查看空压机控制系统中设置的"低压报警"值，或在站房压力表附近标注的报警阈值。"

2. **近14天系统平均压力缺失**: averagePressure 为空或 ≤0
   - 错误信息: "请从监控系统或流量计/压力变送器导出至少连续7天的站房出口总管压力数据（CSV文件，包含时间戳和压力值）。"

3. **空压系统年度总用量缺失**: totalAnnualEnergyConsumption 为空或 ≤0
   - 错误信息: "请提供空压站全年总耗电量（kWh），可根据月度电费单累加。"

4. **无运行设备**: 所有设备的 runningStatus 均不是"运行"或"备用"
   - 错误信息: "请在空压机清单中逐台标注当前状态：运行、备用、故障、停用。至少有一台设备处于"运行"或"备用"状态。"

5. **站房编码为空**: 任意设备的 stationId 为空
   - 错误信息: "请确保每台设备都有站房编码，允许多台设备属于同一站房。"

6. **设备编码重复或为空**: 同一站房内设备 equipmentId 重复，或为空
   - 错误信息: "请确保每台设备有唯一编码。"

### 高严重性错误（影响测算）
检查以下条件，在 highSeverityIssues 中记录：

1. **运行设备铭牌功率缺失**: 任何状态为"运行"的设备，其 ratedPower 为空或 ≤0
   - 错误信息: "请补充运行空压机的铭牌功率（kW）。"

2. **运行设备铭牌流量缺失**: 任何状态为"运行"的设备，其 ratedFlow 为空或 ≤0
   - 错误信息: "请补充运行空压机的铭牌流量（m³/min）。"

3. **设备类型缺失**: 任何设备的 equipmentType 为空
   - 错误信息: "请填写设备类型（螺杆/离心）。"

## 质量检查

提取完成后，请评估数据质量：
- **完整性**: 关键字段的填充率
- **准确性**: 数据格式和数值合理性
- **一致性**: 相关字段之间的逻辑关系
- **打回检查**: 根据打回条件清单进行验证

请在JSON结果中添加质量报告：
```json
{
  "rawData": { /* 原始数据 */ },
  "rejectionCheck": { /* 打回条件检查 */ },
  "quality_report": {
    "completeness": 0.85,

      {
```

## 置信度计算规则

置信度从100%开始，根据以下情况扣分：

| 异常项 | 扣分幅度 |
| --- | --- |
| 压力曲线数据7~14天（不足14天） | -5% |
| 行业缺失（压力波动用默认0.20） | -15% |
| 每台（运行+备用）功率因子使用默认0.35 | -5%/台（最多-30%） |
| 电价缺失（城市推算） | -10% |
| 每天开机时间缺失（默认10） | -5% |
| 年运行天数缺失（默认330） | -5% |
| 年运行时间计算异常（用默认8500） | -10% |
| 品牌缺失 | -5%/台（最多-20%） |
| 出厂年份缺失 | -5%/台（最多-20%） |

最终置信度 = max(0, 100 - 总扣分)
输出时显示：**"high"**（≥80%）、**"medium"**（60~79%）、**"low"**（<60%）

## 使用说明

1. **调用方式**: 通过Claude Agent SDK调用此skill
2. **输入参数**: 文本内容和原始文件名
3. **输出格式**: 包含原始数据、打回检查和质量报告的JSON
4. **处理流程**: 文本分析 → 原始数据提取 → 打回条件检查 → 质量评估 → 结果输出
5. **后续处理**: 输出的原始数据将传递给节能计算技能进行进一步处理

## 重要提醒

1. **必须执行打回检查**: 如果存在致命错误，必须设置 shouldReject = true
2. **数据提取准确性**: 确保从文本中准确提取原始数据，不进行复杂计算
3. **置信度计算**: 根据缺失和推算情况准确计算置信度
4. **数据完整性**: 确保所有必填字段都有值或明确标记为null
5. **职责边界**: 本技能只负责数据提取，不负责计算逻辑
6. **格式标准化**: 输出格式需要便于节能计算技能读取和处理
